# 検証済みの範囲

- タイトルで待機し、STARTでラウンド表示を経て1-1を開始する。
- 原作のタイトルCHR・ネームテーブル・パレットをG-VRAMへ変換し、全面イラストと3項目メニューを表示する。
- 原作の面別台詞とタイトルの顔領域を使い、2.5秒のラウンド開始画面を表示する。
- プレイヤー、敵、矢、3種のアイテム、ボス、背景、ステージ別パレットを原作CHRから変換して表示する。
- STARTでプレイ中の世界とBGMを一時停止・再開する。
- 1-1から1-4まで進行し、ボスを倒した後はエンディングへ遷移する。
- エンディングでSTARTを押すと、新しいタイトル状態へ戻る。
- プレイヤー、敵、矢、アイテム、コイン、ボス、得点、残機、中間地点の規則はホストテストで通る。
- 全4ステージとボスには探索でクリア経路がある。
- Human68k上の68000バイナリがタイトルから開始し、移動とジャンプに反応する。

# 原作との差分

- タイトルとラウンド画面の目パチ、およびタイトルのフェード演出は未移植。
- エンディングは文字表示まで移植したが、原作と文面・配置をまだ完全には揃えていない。
- 被弾エフェクトなど、一部の短い視覚演出は未移植。
- X68000の55.45Hzでもフレーム単位のゲーム規則を保つ方針のため、実時間ではNES版より約8%遅い。

# trust signal

`src/state.s`、`assets/`、`x68k/` の対応箇所を照合した。`just test` はC 170件・Python 12件がすべて成功し、生成器ではNES 2bppからX68000 4bppへの画素変換、タイトル、ラウンド画面を検査した。`just solve` は全4ステージとボスを完走した。`just e2e` はHuman68k上でタイトル全面画像、ラウンド画面、初期状態、ジャンプ、右移動を確認した。現行ランナーのPPM出力はG-VRAMとテキスト面を検証できるが、BG・スプライト面を合成しないため、ゲーム中のPCGは生成器テストとVRAM書き込みのソース監査で検証した。
